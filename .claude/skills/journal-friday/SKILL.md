# Пятничный журнал

## Зачем это

Лента на главной отвечает на пятый, невысказанный вопрос посетителя: «он ещё жив?».
Отстав, она отвечает наоборот — так уже было 31.08.2026, когда строка «обновлено»
показывала дату девятидневной давности. Раз в неделю лента догоняет работу.

## Порядок

1. `node tools/week-log.mjs` — записи за 7 дней по всем репозиториям аккаунта.
   Другое окно: `node tools/week-log.mjs 14`
2. Отобрать кандидатов по правилам ниже
3. Принести владельцу списком: проект, текст по-русски, перевод
4. Для закрытого репозитория — **спросить, как называть проект**. Не придумывать
5. Дождаться явного «да» по каждой записи. Молчание — это не «да»
6. Создать пары файлов, прогнать `npm run check`, закоммитить
7. **Push не делать.** Push в main — это выкат на прод, и решает его владелец

## Что берётся

Тест один: **поймёт ли это владелец салона, который платит за сайт?**

Берётся — примеры из настоящей истории:

- `Прайс: доплаты и товары больше не выдают себя за цену услуги`
- `Задача 115: цены убраны с первого экрана, тексты херо переписаны`
- `Контактная панель: мессенджеры вместо телефона`
- `feat: баннер согласия — счётчики молчат, пока не разрешили`

Не берётся:

| Запись                                                     | Почему нет                         |
| ---------------------------------------------------------- | ---------------------------------- |
| `Pillow в зависимостях: его требует новая проверка srcset` | про инструмент, а не про результат |
| `Manrope одним вариативным файлом, CSS в начало head`      | то же самое                        |
| `docs: форматирование PLAN.md под Prettier`                | служебное                          |
| `Revert "…"`                                               | работа, которой не было            |
| `Задачи 73, 75, 76 закрыты отказом`                        | не сделано, а отменено             |
| `Задача 98: actions подняты с Node 20 на Node 24`          | внутренняя кухня                   |

**Если за неделю брать нечего — не берём ничего.** Честное молчание лучше записи
ради записи: лента без наполнителя читается как работа, с наполнителем — как отчёт.

## Одна работа — одна запись

История дробится мельче журнала. Склеивать обязательно:

- **серия по одной задаче.** `Задача 104` идёт тремя записями подряд про перелив
  в знаке — это одна строка журнала, а не три;
- **одно и то же в двух проектах.** `Мобильное меню дёргалось при прокрутке
на планшете` лежит и в `vn.neva.beauty`, и в `th.neva.beauty` одним числом.
  Это одна запись про оба сайта.

Больше трёх-четырёх записей за неделю приносить не надо. Лента на главной
показывает пять строк, и одна пятница не должна вытеснять из неё всё остальное.

## Чего наружу не идёт никогда

- имена файлов, пути, названия веток;
- номера внутренних задач: `Задача 115: цены убраны` → `цены убраны`;
- любые числа доступа — ключи, токены, номера счётчиков. В истории такое
  встречается прямо в заголовках записей;
- персональные данные и имена клиентов, на которые нет разрешения;
- содержимое закрытых репозиториев без разрешения владельца на конкретную запись.

## Как пишется текст

- **результат, а не действие.** «Счётчики молчат, пока не разрешили» — да.
  «Добавил баннер согласия» — нет;
- одно предложение, до 140 знаков: длиннее не пропустит схема;
- русский — источник истины, английский переводится с него;
- без жаргона. Читатель не разработчик.

## Это точно апдейт?

Три вопроса на случай, если запись выросла:

| Отвечает на…                      | Это     | Куда                                |
| --------------------------------- | ------- | ----------------------------------- |
| «что случилось»                   | апдейт  | `src/content/updates/`              |
| «как это работает» / «почему так» | заметка | `src/content/notes/`, своя страница |
| «что я сделал для клиента»        | кейс    | навык `case-writer-repo`            |

## Файлы

`src/content/updates/ru/<ГГГГ-ММ-ДД>-<слаг>.md`:

```yaml
---
date: 2026-09-05
project: vn.neva.beauty
text: >-
  Прайс на сайте салона перестал путать: доплаты и товары больше не выглядят
  как цена услуги.
---
```

`src/content/updates/en/<тот же слаг>.md` — **только** поле `text`. Дата и проект
живут в русском документе; их копию `check:journal` не пропустит.

Дата в начале слага: у апдейта нет своего адреса, слаг — просто имя файла. Дата
спереди держит папку в хронологическом порядке и снимает совпадения имён, которые
за год еженедельных записей неизбежны.

Поле `project` обязательное — в том числе у записи про сам сайт (`jw-dev.pro`).
Лента смешивает работу по нескольким проектам, и строка без подписи в таком списке
читается не как «это про сайт», а как забытое поле.

## Проверка

`npm run check` — среди прочего `check:journal`: пара RU↔EN, формат слага, дата
не из будущего, отсутствие полей источника в английском документе.
