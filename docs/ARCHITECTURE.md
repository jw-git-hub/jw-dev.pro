# Архитектура jw-dev.pro

Как устроен репозиторий. Документ живой: меняется код — правится здесь же,
а не дописывается в журнал.

## Что это

Статический сайт-визитка. Astro собирает `dist/` из контента и шаблонов, Nginx на VPS
раздаёт готовые файлы. Рантайм-фреймворка в браузере нет, серверного рендеринга нет.
Единственный серверный кусок — приёмник формы (фаза 9), и он нужен только потому,
что доставка заявки требует секрета.

```
контент (md) ─┐
данные (ts)  ─┼─► Astro (сборка) ─► dist/ ─► Nginx (VPS) ─► браузер
строки (json)─┘                                  │
                                                 └─► /api/contact ─► contact-api (Python)
```

## Три слоя контента

Их нельзя путать — у каждого свой владелец и свой цикл изменений.

| Слой              | Где               | Кто правит             | Пример                                |
| ----------------- | ----------------- | ---------------------- | ------------------------------------- |
| Контент           | `src/content/`    | владелец, без кода     | текст кейса, статья журнала           |
| Данные интерфейса | `src/data/`       | владелец + разработчик | направления, шаги процесса, стек, FAQ |
| Строки интерфейса | `src/i18n/*.json` | разработчик            | «Смотреть работы», «Отправить»        |

Строки подставляются **на сборке**. Клиентского словаря нет: в браузер не уезжает ни одного
килобайта переводов, текст не мигает при загрузке, обе языковые версии видит поиск.

## Коллекции контента

Схемы — в `src/content.config.ts`, поля описаны в `CONTENT-CASES.md §1`.

```
src/content/
  cases/ru/<slug>.md      источник истины: все поля кейса и русский текст
  cases/en/<slug>.md      перевод: только переводимые поля
  cases/shots/<slug>/     мастер-кадры, общие для обоих языков
  notes/{ru,en}/          заметки журнала (фаза 8)
  updates/{ru,en}/        апдейты одной строкой (фаза 8)
```

**Русский документ несёт языконезависимые поля** — `order`, `tech`, `link`, `date`,
`accent`, `shotKind`, `screenshots[].src`. Английский переводит `kind`, `summary`,
`metrics`, `logLine`, `body` и `alt` снимков. Второй копии ссылки или даты
не существует, поэтому им негде разъехаться, а пару стережёт `check:content`.

**Имя файла — это слаг адреса** `/work/<slug>/`. Отдельного поля `slug` нет
намеренно: две записи одного и того же однажды разойдутся.

`zod` импортируется напрямую из пакета, а не из `astro:content`: в Astro 7
реэкспорт `z` объявлен устаревшим и подсвечивает каждое обращение.

## Языки

`astro.config.mjs` → `i18n.routing.prefixDefaultLocale: false`. Английский живёт на `/`,
русский — на `/ru/`. Страницы русской версии лежат в `src/pages/ru/`.

Русский текст — источник истины, английский переводится с него. Поэтому `useTranslations`
при отсутствии ключа в EN отдаёт русскую строку, а не имя ключа: непереведённый текст
лучше, чем `stub.title` на живом сайте. Дыры ловит `tests/check-i18n.mjs` до деплоя.

`src/i18n/index.ts`:

- `localeFromUrl(url)` — язык по адресу;
- `useTranslations(locale)` — функция `t(key)`;
- `localizePath(pathname, target)` — тот же путь на другом языке, для переключателя и hreflang.

## Маршруты и обвязка страницы

```
/                 /ru/                главная
/log/             /ru/log/            архив журнала
/privacy/         /ru/privacy/        политика
/404              /ru/404             страница ошибки
```

Все страницы собираются каталогами (`/log/` → `log/index.html`), включая обе
страницы ошибки. Nginx отдаёт их через `error_page`: английскую — на весь сайт,
русскую — для путей под `/ru/`, иначе посетитель русской версии на первой же битой
ссылке получал бы английский текст.

У страницы ошибки нет ни `canonical`, ни `hreflang`, а переключатель языка ведёт
на главную: «этой же страницы на другом языке» не существует, и врать поисковику
об этом нельзя.

Обвязка страницы живёт в `src/components/chrome/` и подключается один раз
в `BaseLayout`: шапка, шторка разделов, подвал, док.

Блоки главной — в `src/components/home/` (`Hero`, `HeroStage`, `HeroWindow`,
`MetricPanel`, `Stats`), слот скриншота и условная вёрстка внутри него —
в `src/components/shot/` (`ShotSlot`, `SiteMock`, `ChatMock`). Слот вынесен отдельно
намеренно: сейчас его показывают окна героя, в фазе 6 те же слои возьмут карточки
кейсов, и класть общий компонент в папку одного из двух потребителей нечестно.

**Шапка** фиксированная; класс `stuck` вешает `header.js` после 18px прокрутки.

**Шторка разделов** — настоящий `<details>` с `<summary>` вместо бургера: меню
обязано открываться без JS. Она начинается под шапкой, поэтому бургер остаётся
виден и закрывает её повторным нажатием. Скрипт добавляет Esc, блокировку
прокрутки и `inert` для содержимого под шторкой.

Пока шторка открыта, шапка отдаёт ей блюр: элемент с `backdrop-filter` создаёт
backdrop root, и вложенный фильтр размывает только содержимое родителя.

**Док** появляется после 55% высоты экрана и прячется при движении вниз
с гистерезисом. В покое он `visibility: hidden`, а не просто прозрачный:
невидимый, но фокусируемый элемент — ловушка для клавиатуры.

## Стили

Только глобальные файлы в `src/styles/`. Точка входа одна — `main.css`, она же задаёт
порядок каскада; в `BaseLayout.astro` подключается только она, Vite склеивает импорты
в один файл на сборке. Блоков `<style>` внутри компонентов не бывает — причины
в `CLAUDE.md`.

```
main.css                порядок каскада, единственный импорт в шаблоне
fonts.css               @font-face своего шрифта, два подмножества
tokens.css              §1: цвета, радиусы, easing, шрифты, зерно
accent.css              §2: тройки --acc/--acc-ink/--acc2 по имени акцента
tone.css                акцент карточки: шесть классов вместо инлайнового --cc
reset.css               сброс браузерных умолчаний
base.css                документ, глобальная типографика §3, пол доступности §18
layout.css              контейнер, ритм секций, утилиты, справка по брейкпоинтам §17
motion.css              появление .rv, общие кейфреймы, выключение движения
components/*.css        по файлу на компонент: backdrop, glass, button, pill,
                        header, lang, mnav, dock, footer, mark, shot, hero, stats
```

Имена классов взяты из гайда как есть: `.g`, `.gd`, `.rv`, `.btn.p`, `.irid`. Они короче,
чем принято в проекте, но гайд вместе с макетом — контракт: переименуешь — и справочник
станет непригоден. Что означает короткое имя, объясняет комментарий в начале файла.

Типографика уровня документа (h1–h3, `.lead`, `.mono`, `.kick`) живёт в `base.css`.
Кегли внутри компонентов — в файлах этих компонентов, иначе `base.css` превращается
в свалку. Кейфрейм лежит в `motion.css`, только если его использует больше одного
компонента; одиночные — рядом со своим.

Автопрефиксера в сборке нет, префиксы написаны руками, и правила Stylelint про них
выключены осознанно (`stylelint.config.js`): iOS понимает только
`-webkit-text-size-adjust`, Safari до 18 — только `-webkit-backdrop-filter`, а маска
рамки `.irid` без `-webkit-mask-composite` в WebKit не собирается. Сокращения `mask`
пишутся **до** `mask-composite`: `-webkit-mask` — псевдоним `mask` и сбрасывает
композитинг к начальному значению, из-за чего рамка превращается в заливку.

`--acc`, `--acc-ink` и `--acc2` зарегистрированы через `@property` — без этого смена
акцента секции не анимируется: браузер считает незарегистрированную переменную строкой,
а строки не интерполируются. Сами тройки лежат в `accent.css` под селекторами
`html[data-acc='…']`, а не подставляются из скрипта: значение цвета в проекте
существует ровно в одном месте.

Акцентов в тройке два не случайно. `--acc` заливает, `--acc-ink` пишет и обводит,
и различаются они только у индиго: `#4F46E5` даёт 3,16:1 на фоне и 2,92:1 на стекле —
ниже порога AA и для текста, и для обводки фокуса, а индиго ведёт три секции из
одиннадцати. Подробности и таблица — `DESIGN-GUIDE.md §1`. Правило при вёрстке:
**фон — `--acc`, пиксели текста и линии, которые надо разглядеть, — `--acc-ink`.**

Ховер-правила живут под `@media (hover: hover) and (pointer: fine)`, по одному блоку
в конце файла компонента. На тач-экране `:hover` срабатывает по тапу и залипает до
следующего касания. Блок стоит в конце, потому что ховер обязан идти после базового
состояния; там, где специфичность совпадает с состоянием (`.fbtn[aria-pressed]`),
селектор дополнен `:not()`, иначе переезд вниз перекрасил бы активный элемент.

## Шрифт

Onest, переменный, OFL-1.1. Лежит в `public/fonts/` двумя подмножествами woff2:
кириллица 14 КБ и латиница 32 КБ; `cyrillic-ext` и `latin-ext` не берём — это языки,
которых на сайте не будет, а ещё 18 КБ веса. Лицензия рядом, `LICENSE-onest.txt`.

Файл свой, с того же домена: «ноль внешних запросов» соблюдено, CSP уже разрешает
`font-src 'self'`. `unicode-range` в `fonts.css` обязателен — без него браузер тянет
оба подмножества на любой странице. В `<head>` предзагружается подмножество своего
языка, с `crossorigin`: шрифты качаются в режиме CORS, и без атрибута preload
не засчитывается, файл скачается дважды.

Шрифт учитывается в бюджете веса: `check-budget.mjs` прибавляет вес всех `.woff2`
к каждой странице. Собрать их по ссылкам из разметки нельзя — подмножество выбирает
CSS через `unicode-range`, — поэтому бюджет считает пессимистично.

Моноширинный остался системным: он живёт на подписях 10–12px, где разница гарнитур
не читается, а второй файл стоил бы дороже пользы.

## Скрипты

`src/scripts/`, ES-модули, по файлу на поведение. Слушатели вешаются только
из модулей: атрибутов `on*=` в разметке нет.

```
header.js           состояние шапки при прокрутке
nav.js              надстройка над шторкой разделов
dock.js             кольцо прогресса и правило показа дока
reveal.js           появление .rv и предохранитель
accent.js           какая секция читается сейчас и какого она цвета
pointer.js          свет за курсором, параллакс ауроры, публичный onPlane
parallax.js         сцена героя: окна, HUD и каустики от курсора и прокрутки
counters.js         счётчики чисел статистики
graph.js            фоновая сеть: канвас, цикл, тинт, публичный setTint
graph/paint.js      палитра из токенов и примитивы канваса
graph/field.js      узлы и рёбра между ними
graph/anchors.js    привязка к элементам [data-nx]
graph/pulses.js     импульсы по рёбрам
graph/damp.js       дыры под текстом
lib/scroll.js       подписка на прокрутку не чаще кадра
lib/motion.js       запрос «меньше движения» из системных настроек
```

Глобального `window.__graph` из гайда нет: модули связаны импортами, и акцент
зовёт `setTint` напрямую. `start`, `stop` и `remeasure` станут экспортами тогда,
когда их спросят оверлеи (Ф6) и журнал (Ф8): экспорт без потребителя — мёртвый код.

При `prefers-reduced-motion` граф не выключается, а переходит в статичный кадр
(`staticFrame`): цикл не заводится, искр нет, узлы не мерцают, но рёбра и нити
якорей на месте — без них стекло висит над пустотой, чего `DESIGN-GUIDE §5` не
допускает. Кадр перерисовывается при прокрутке и смене акцента через `requestStatic`:
канвас фиксирован, а якоря привязаны к элементам, которые уезжают. Это не анимация,
а то же самое, что делает любой `fixed`-слой.

Ни одного значения цвета в скриптах нет. Акцент переносится на `<html>` именем,
пары цветов берёт `accent.css`, а граф снимает палитру с `:root` при старте.
Правка токена подхватывается везде сразу.

Скрипты — надстройка, а не условие работы. Без них шапка остаётся шапкой, меню
открывается силами `<details>`, док просто не показывается, а блоки `.rv` видны
сразу — это берёт на себя `@media (scripting: none)` в `motion.css`.

## Фон и движение

Четыре фиксированных слоя под контентом собраны в `Backdrop.astro`. Порядок задаёт
z-index, а не разметка: аврора 0, вуаль 1, граф и свет 2, контент 3, шапка 50,
зерно 60. Все слои декоративные и целиком `aria-hidden`.

Граф — единственный `requestAnimationFrame` на странице. Он останавливается на
скрытой вкладке и не запускается при `prefers-reduced-motion`. Геометрия якорей
и дыр пересчитывается раз в 560 мс: `getBoundingClientRect` заставляет браузер
пересчитать layout, и делать это каждый кадр ради неподвижных блоков незачем.

Элемент попадает в сеть атрибутом `data-nx` и гасит её под собой атрибутом
`data-damp`. Списка селекторов у графа нет намеренно: компонент, которому сеть
мешает или на которой он висит, объявляет это у себя, а не строчкой в чужом файле.

Канвас растягивается процентами, а не `inset: 0`. Он замещаемый элемент: при
`width: auto` браузер оставляет ему размер растра и правый упор игнорирует.

## Герой и статистика

Сцена героя — три окна, четыре HUD-пилюли и три каустика на разной глубине. Всё
покадровое движение сводится к четырём пользовательским свойствам: `parallax.js`
пишет `--dx/--dy/--rx/--ry` через `style.setProperty`, а сами `transform` собраны
в `hero.css`. Это единственное разрешённое исключение из правила «ноль инлайна»:
CSSOM, а не атрибут в разметке.

Глубина `--tz` в этот список не входит — она статична и живёт в CSS у класса позиции.
В макете её ставил скрипт из `data-tz`, и без JS сцена схлопывалась в плоскую
аппликацию; теперь объём есть всегда. Обратная сторона: при `prefers-reduced-motion`
сцену приходится распрямлять явно, поэтому `.hud` дописан к списку `transform: none`
в `motion.css` рядом с `.win` и `.stage-in`.

Своего цикла у параллакса нет. Положение курсора приходит уже сглаженным из
`pointer.js` через `onPlane`: второе такое же сглаживание в отдельном цикле
разъезжается с первым на доли кадра, и слои начинают дрожать друг относительно друга.
Прокрутку сцена берёт из общего `onScroll`, а когда уходит с экрана — перестаёт
считать вовсе (`IntersectionObserver` на `.stage`). Ниже 901px параллакса нет:
там сцена схлопнута в колонку и `transform: none`.

Якорь фоновой сети (`data-nx`) висит не на самом окне, а на слое дрейфа внутри него:
`getBoundingClientRect()` не видит трансформ ребёнка, и нить оставалась бы там, где окно
было бы без покачивания. Параллакс граф всё равно догоняет с задержкой — геометрия
якорей пересчитывается раз в 560 мс, и это осознанный размен: мерить семь элементов
каждый кадр значит заставлять браузер пересчитывать layout шестьдесят раз в секунду.

Счётчики устроены наоборот: финальное число стоит в разметке, а `counters.js` только
отматывает его назад и досчитывает при появлении карточки. Отматывает при этом лишь то,
чего сейчас не видно: карточка проявляется на 6% видимости, счёт стартует на 40%, и без
этого правила посетитель успевает прочитать «7» до того, как оно прыгнет в ноль. Без JS
и при reduced-motion скрипт не делает ничего — цифра уже верная. Диапазон считается
от своей нижней границы (`data-from`), иначе «94–98» по дороге показывает «94–37».

## Сборка: два неочевидных параметра

**`build.inlineStylesheets: 'never'`** — по умолчанию Astro вшивает мелкие стили прямо
в `<style>` в разметке. Это ломает CSP без `unsafe-inline` и лишает стили отдельного
кеша. Не менять.

**`vite.build.assetsInlineLimit: 0`** — Astro вшивает маленькие модули прямо
в `<script>` в разметке, ровно как и мелкие стили. Ноль отключает порог. Значение
живёт в `vite`: ключа `build.assetsInlineLimit` у Astro нет, в конфиге он молча
игнорируется, и скрипт как вшивался, так и вшивается.

**`compressHTML: true`** — в Astro 7 значение по умолчанию `'jsx'`: пробел между
строчными элементами съедается по правилам JSX, и `<span>раз</span> <em>два</em>`
превращается в «разадва». Нам нужны правила HTML.

Компилятор Astro 7 — на Rust, он строг к невалидной разметке: незакрытый тег теперь
ошибка сборки, а невалидную вложенность он больше не исправляет молча. Для этого
проекта это плюс.

## Ворота

`npm run lint` — ESLint, Stylelint, Prettier.

`npm run check`:

| Проверка        | Что ловит                                            |
| --------------- | ---------------------------------------------------- |
| `check:astro`   | типы и ошибки шаблонов                               |
| `check:content` | пару RU↔EN, длины полей, размер и вес мастер-кадров  |
| `check:i18n`    | ключ есть в одном языке и отсутствует в другом       |
| `check:css`     | брейкпоинт, easing, радиус блюра или цвет мимо гайда |
| `check:inline`  | инлайн-стили, инлайн-скрипты, обработчики `on*=`     |
| `check:html`    | валидность разметки и доступность на собранном HTML  |
| `check:links`   | внутренние ссылки, ведущие в никуда                  |
| `check:budget`  | вес CSS, JS и страницы целиком                       |

Те же команды выполняет CI. Красное — деплоя нет.

`check:inline` пропускает `<script type="application/ld+json">`: это блок данных для
поисковых систем, браузер его не исполняет, и CSP его не блокирует.

`check:astro` требует пакета `@astrojs/check`. Без него `astro check` спрашивает
разрешение поставить его и выходит с нулём: ворота зелёные, при этом не проверено
ничего. Пакет держим в devDependencies.

`check:content` делит работу с Astro осознанно: типы и длины полей проверяет zod
на сборке, а скрипт берёт то, что схемой не выражается, — существование английской
пары, счёт предложений в абзацах, уникальность `order` и соответствие мастер-кадров
регламенту §3 (размер под роль, вес до 400 КБ). Кейсы без снимков он не роняет,
а печатает списком: снимки ждут владельца.

## Деплой

`deploy/nginx.conf` — раздача статики, кеш-заголовки, CSP без `unsafe-inline`.
`deploy/docker-compose.yml` — Nginx; контейнер `contact-api` добавится в фазе 9.
`.github/workflows/deploy.yml` — выкат по `rsync --delete`, пока запускается руками.

Секреты живут в `.env` на сервере и в секретах репозитория, в код не попадают никогда.
