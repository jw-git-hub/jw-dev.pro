## Контекст

Есть домен `jw-dev.pro` (пока не куплен), знак `>jw_` и утверждённая концепция дизайна.

Три файла в папке проекта — **не техзадание, а разные вещи**:

- `13-final.html` — визуальный макет. Нужен, чтобы понять, как сайт выглядит и движется.
  Состав разделов, тексты, цены, шаги процесса и цифры в нём — **демонстрационные, за правду
  не берутся**.
- `DESIGN-GUIDE.md` — визуальный язык: токены, стекло, тайминги, брейкпоинты, две фирменные
  механики. **Это обязательно к исполнению.**
- `CONTENT-CASES.md` — регламент описания кейса: поля, размеры скриншотов, чек-лист. Полезен как
  схема данных.

Структуру сайта, тексты и состав блоков проектируем с нуля. Из макета берётся только визуальный
язык.

Факты о проектах берутся из восьми публичных репозиториев `github.com/jw-git-hub`, а не из макета.

## Часть 1. Анализ: что должно быть на сайте-визитке разработчика

### Посетитель приходит с четырьмя вопросами

1. **«Кто это и что делает?»** — одно предложение, без «команды профессионалов».
2. **«Он умеет?»** — доказательства: живые ссылки, цифры, скриншоты с видимыми числами,
   публичный код. **Это подтверждено:** восемь репозиториев открыты, два сайта живы прямо сейчас,
   бот отвечает по нажатию кнопки.
3. **«Что я получу и на каких условиях?»** — что входит, кому принадлежит код, есть ли подписка,
   сколько занимает. Цен пока нет — стоимость называется после разбора задачи.
4. **«Как связаться?»** — низкий порог входа: не «оставьте заявку», а «пришлите ссылку —
   верну отчёт».

Пятый вопрос вслух не задают: **«он ещё жив?»**. Портфолио без даты последнего обновления
читается как заброшенное. На это отвечает журнал — поэтому он несущий элемент, а не украшение.

### Что обязано быть, чего в макете нет

| Чего нет                             | Почему это не косметика                                                                    |
| ------------------------------------ | ------------------------------------------------------------------------------------------ |
| Свои адреса у кейсов и статей        | Первый контакт — ссылка, отправленная в Telegram. Отправить нечего: весь сайт на одном URL |
| Превью ссылки в мессенджере (OG)     | Без него ссылка — голый текст. Один OG на весь сайт = все кейсы неотличимы                 |

| sitemap, robots, canonical, hreflang | Без hreflang две языковые версии конкурируют как дубли                                     |

### Чего делать не надо

- **Отзывы** — их нет в письменном виде. Выдуманный обесценивает настоящие цифры рядом.

  задачи. Придуманная цена хуже её отсутствия: она либо отсекает нормальные заказы, либо
  приводит те, от которых придётся отказываться.
  **Правка 25.08.2026:** цифры в FAQ — не прайс-лист, а условия, и они настоящие: владелец
  назвал часовую ставку, вилки поддержки, порог дробления оплаты и стоимость домена
  и сервера. Цена за проект по-прежнему не публикуется.
- **Планета вместо фоновой сети** — отклонено владельцем 28.08.2026 по внешнему виду.
  Прототипы собраны, измерены и удалены; цифры сохранены здесь, чтобы работу не делать
  дважды. На профиле ворот (CPU ×4) разницы нет вовсе: оба фона держат 60 кадров без

## Часть 5. Архитектура

### Три слоя, которые нельзя путать

1. **Контент** — markdown с front-matter, схема проверяется на сборке. Правится без кода.
2. **Данные интерфейса** — направления, стек, шаги процесса, FAQ, контакты. Один файл на сущность.
3. **Строки интерфейса** — `src/i18n/ru.json` (источник) и `en.json` (перевод), подставляются
   **на сборке**. Клиентского словаря нет, мигания текста нет, обе версии видит поиск.

Механика `data-i18n` из макета не переносится — это главное упрощение проекта.

### Технические стандарты (обязательны, отступлений нет)

**Ноль инлайна в отдаваемом HTML.** Ни `<style>`, ни `<script>` в разметке, ни атрибутов `style=`,
ни обработчиков `onclick=`. Всё во внешних файлах с хешем в имени. Только так включается строгий
CSP без `unsafe-inline`, и только так стили и скрипты кешируются отдельно от HTML.

| В макете                                             | В проде                                                                   |
| ---------------------------------------------------- | ------------------------------------------------------------------------- |
| `style="--cc:#94A3B8;--cardc:…"` на карточке         | класс-модификатор `.case--slate`; палитра акцентов закрытая, цветов шесть |
| `style="padding-top:0"`, `style="text-align:center"` | утилитарные классы в `layout.css`                                         |
| `style="--h:48%"` на столбиках HUD                   | классы-ступени, значения заданы дизайном                                  |
| `<style>` на 830 строк                               | `src/styles/*.css`, хеш в имени, `immutable`                              |
| `<script>` на 1030 строк                             | ES-модули, загрузка по потребности                                        |
| фавикон как `data:` URI                              | `favicon.svg`, `.ico`, apple-touch-icon, `site.webmanifest`               |

Единственное исключение — `element.style.setProperty()` из JS для покадровых `transform`
и `opacity` в кольце стека, параллаксе и импульсе процесса. Это CSSOM, а не инлайн в разметке;
CSP такое не блокирует, и покадровой анимации без него не существует.

**Заголовки безопасности** (Nginx): CSP без `unsafe-inline` и `unsafe-eval`, HSTS с preload,
`X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
`Permissions-Policy`, `frame-ancestors 'none'`. Метрика — единственное послабление, прописанное
явными доменами.

**Разметка.** Семантический HTML5: один `<h1>` на страницу, уровни заголовков без пропусков,
`<article>`, `<nav aria-label>`, `<time datetime>`, корректные landmarks. Валидатор W3C без
ошибок — в CI.

**Доступность — WCAG 2.2 AA**: контраст, видимый фокус, полная работа с клавиатуры, скринридер,
`prefers-reduced-motion`.

**Прогрессивное улучшение.** Без JS работают навигация, кейсы, статьи, журнал и переключение
языка. Форма без JS отправляется обычным `POST` и возвращает страницу-ответ.

**Гигиена репозитория.** ESLint + Stylelint + Prettier, `.editorconfig`, pre-commit хук,
Conventional Commits, `package-lock.json` в репозитории, версии зафиксированы, секреты только
в `.env` на сервере.

**Ворота CI до деплоя:** сборка → линтеры → схема контента → полнота переводов → битые ссылки →
валидатор W3C → бюджет веса → Lighthouse CI. Красный любой — деплоя нет.

подвал, нижний док (§14), skip-link, i18n-каркас, все роуты-заглушки на обоих языках,
переключатель языка как ссылка.
**Готово когда:** все маршруты открываются на обоих языках, hreflang проставлен, клавиатура
проходит меню и док без ловушек.

### Ф3. Фон и движение

Aurora, veil, свет за курсором (§1). Canvas-граф (§9) с привязкой `data-nx`, импульсами
и демпфированием под текстом. Механика акцента секции (§2). Появление `.rv` с предохранителем.
Полное выключение по `prefers-reduced-motion`.
**Готово когда:** акцент плавно меняется по секциям, граф держит 60 fps, при reduced-motion
страница статична и читаема.

### Ф4. Герой и статистика

3D-сцена из трёх окон, четыре HUD-пилюли, каустики, параллакс от курсора (§10). Счётчики цифр
со страховками.
**Готово когда:** на ≤900px сцена схлопывается в колонку, заголовок остаётся над сценой,
счётчики досчитывают при любом раскладе.

**Из ревизии 22.08.2026 (C3) — решено:** измерено на живой странице. При отступе
`clamp(76px, 9.5vw, 148px)` соседние блоки расходятся на 296px (274 при ширине 1440) —
на ноутбучном окне 784px это больше трети экрана, и занять его нечем: вуаль гасит
аврору, рёбра графа идут на альфе 0,18. Срезано до `clamp(64px, 7vw, 112px)`:
между блоками 224px, блоки не слипаются, дыры нет. §4 гайда правлен, отступление
записано там же с датой. Второй инструмент — `.sec-flush`: статистика стоит вплотную
к герою и читается как подпись под первым экраном.

### Ф5. Контент-слой

Схемы коллекций по `CONTENT-CASES.md §1`. Черновики семи кейсов на русском из описаний и README
репозиториев, затем перевод на английский. `src/i18n/ru.json` → `en.json`. Данные интерфейса.
Пайплайн картинок. `check-content` и `check-i18n` в CI.
**Готово когда:** `npm run check` зелёный, тексты приходят из файлов, у каждого RU-документа
есть EN-пара.

### Ф6. Кейсы

Сетка с тремя состояниями карточки (обычная / живое демо / закрытое демо), фильтры с живым
счётчиком, страницы `/work/<slug>/`, оверлей с History API, навигация «предыдущий/следующий»,
OG-картинка на кейс.
**Готово когда:** прямая ссылка открывает страницу, клик с главной — оверлей и меняет адрес,
«назад» возвращает на главную, ссылка даёт превью в Telegram.

**Из ревизии 22.08.2026 (C5):** слот `.shot` занимает больше половины высоты карточки
и рисует поверх скриншота фальшивую панель браузера с тремя кружками. Посетитель и так
смотрит сайт в браузере — вторая рамка добавляет только высоту, и это самый растиражированный
приём в портфолио разработчиков. Сильное в слоте другое — `.shot-veil`, который уводит пёстрый
скриншот в палитру карточки и отпускает на ховере; он работает и без кружков. Предложение:
кружки убрать, освободившиеся ~40px отдать чипам метрик. Решает владелец — это §8 гайда.

### Ф7. Направления, стек, процесс

Три карточки направлений без цен. Кольцо стека (§12): три яруса, перетаскивание, легенда
с фильтром, оба состояния — кольцо и плоский ряд пилюль. Процесс (§11): SVG-путь, импульс
на 12 000 мс, пять узлов, пиннинг шага, вертикальная рельса на ≤900px.
**Готово когда:** обе механики работают мышью и клавиатурой, оба состояния каждой проверены,
циклы встают при уходе секции из вьюпорта.

**Из ревизии 22.08.2026 (C4):** кольцо — одна из двух механик, «ради которых этот дизайн
и выбран» (§12), но по §17 оно выключается на ≤900px, то есть достаётся меньшинству трафика.
На самом кольце чипы дальней стороны сжимаются до ~9px и налезают друг на друга (на макете
«Web Components» лежит поверх «no framework by default»). Порядок работы поэтому обратный
макету: **сначала** плоский ряд — сгруппированная сетка чипов, хорошая сама по себе, —
и только поверх него кольцо на десктопе. Тогда мобильный не выглядит обрезанным.

### Ф8. Журнал

Лента на главной, архив `/log/` с табами и счётчиками, страницы статей, блоки кода, RSS на оба
языка, «последняя запись N дней назад» считается из данных.
**Готово когда:** статья открывается по прямой ссылке, RSS валиден, счётчики табов совпадают
с содержимым.

**Закрыто 22.08.2026.** Четыре страницы статей (две заметки × два языка), `/log/` на обоих
языках, две ленты RSS по девять записей. Решение владельца: архив — страница, оверлея `.arc`
не будет. Подсветка кода — Prism, а не Shiki: Shiki проставляет `style=` на каждом токене
и валит правило «ноль инлайна».

### Ф9. About, FAQ, контакты

Блок About с вращающимися кольцами, аккордеон FAQ во всю ширину, форма, `contact-api`
в контейнере, антиспам, тост копирования почты, работа формы без JS.
**Готово когда:** заявка с прода доходит в Telegram и на почту, ловушка ловит бота, ошибки полей
показываются и озвучиваются скринридером.

### Ревизия маркетинга и текстов

Аудит того, что написано, а не того, как выглядит. Причина одна на все находки: тексты
и цифры главной собраны по образцу `13-final.html`, а он — визуальный макет с
демонстрационным наполнением. Правило «макет — только внешний вид» нарушено в текстах.

**Три находки владельца от 22.08.2026 — все закрыты 25.08.2026:**

1. ~~**Панель Lighthouse 96 в герое**~~ (`hero.panel*` в `i18n`). Было: метрика одного
   чужого сайта на главном экране. Стало: `Открытый код · 8 · репозиториев на GitHub` —
   то, что можно проверить до оплаты. Замер Lighthouse остался в разборе
   `vn.neva.beauty`, где названы версия инструмента, профиль и число прогонов.
2. ~~**Пилюля «Цены / 204 в одном файле»**~~ (`hud.prices`). Стало:
   `Цены / правятся в одном месте`. Факт тот же, но названа польза,
   а не внутренняя деталь реализации.
3. ~~**Гео в подзаголовке**~~ — закрыто 25.08.2026 решением владельца: города на сайте
   нет нигде, в подзаголовке стоит «работаю онлайн», в About — только часовой пояс
   и языки. Работа ведётся онлайн, откуда именно — покупателю безразлично, а факт был
   вдобавок неверен.

**Что нашла ревизия сверх трёх пунктов:**

- `hero.sub` продавал ту же чужую метрику и перечислял этапы работы вместо условий
  сделки. Стало: что делаю целиком, разбор бесплатный, код и доступы после сдачи ваши.
- Пилюли `Статус / Онлайн` и подписи статистики говорили на языке разработчика
  («Lighthouse», «автотестов», «репозиториев»). Переписаны обычными словами; правило
  «понятное слово вместо короткого» действует и на тексты сайта.
- `footer.note` обещал «собрано без фреймворков», хотя сайт собран на Astro. Обещание
  относится к браузеру — там нет ни одной внешней библиотеки, так и написано.
- `sec.stack.s` отправлял читателя за примерами «ниже», хотя кейсы стоят выше секции.
- «Телеграм-бот» и «Telegram-бот» жили в текстах одновременно. Везде латиницей.
- Английский надзаголовок и заголовок секции направлений были переставлены местами
  относительно русского.

**Готово когда:** каждая строка главной отвечает на вопрос посетителя из Части 1, а не
демонстрирует внутренности проекта; ни одной формулировки, перенесённой из макета без
решения владельца; ни одной цифры, которая продаёт чужой сайт вместо услуги.

**Итог 25.08.2026:** первые два условия выполнены. По третьему четыре строки макета
оставлены сознательно и вынесены на подтверждение владельца — они не врут, но решения
по ним не было.

### Ф10. SEO и шаринг

Мета и canonical, OG/Twitter-карточки, JSON-LD (Person, ProfessionalService, Article,
BreadcrumbList), sitemap, robots, 404 в дизайне сайта, фавиконы и `site.webmanifest`, Метрика
отложенно и с разрешением в CSP, `/privacy/` и строка согласия под кнопкой отправки.
**Готово когда:** каждый тип страницы даёт корректное превью в Telegram, JSON-LD проходит
валидатор, Метрика работает при строгом CSP и не роняет Lighthouse.

**Итог 25.08.2026.** Сделано: карточка шаринга у каждого типа страницы (главная, архив,
статья, кейс) вместо картинок у одних кейсов; граф schema.org — `WebSite`, `Person`
и три `Service` на главной, `Article` с `BreadcrumbList` на кейсе и статье; иконки
для iOS и Android, растеризованные из того же `favicon.svg`, и манифест на обоих языках;
Метрика отложенная, без вебвизора, с тремя источниками в CSP; политика с текстом,
написанным по коду; `/sent/` и `/not-sent/` убраны из карты сайта.

Два отступления от плана:

1. **`Service` вместо `ProfessionalService`.** Второй — подтип `LocalBusiness`, то есть
   заявка на заведение с адресом, а гео на сайте нет нигде по решению владельца
   от 25.08.2026. Разметка, объявляющая место, которого страница не показывает, —
   ровно то расхождение, которое разметка и должна исключать.
2. **`favicon.ico` не собирается.** PNG 32×32 закрывает те же случаи, а `.ico` sharp
   не пишет: пришлось бы держать в репозитории картинку, собранную вне сборки.

Проверено локально: структура графа, разрешение ссылок `@id`, наличие всех файлов
превью, отсутствие noindex-страниц в карте сайта — воротами `check:seo`; вокабуляр
`Service` сверен со schema.org. **Осталось на прод:** превью в Telegram и онлайн-валидатор
schema.org — то и другое требует живого домена. Влияние счётчика на Lighthouse меряется
в Ф11 и только с настоящим номером: без него счётчика в сборке нет.
