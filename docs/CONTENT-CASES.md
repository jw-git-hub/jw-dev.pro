# CONTENT-CASES — как описывать проекты

Этот файл — инструкция владельцу. По ней вы описываете каждый законченный проект один раз,
кладёте рядом скриншоты, и агент-разработчик вставляет всё это в сайт без вопросов и без домысливания.

Кейс на этом сайте живёт сразу в трёх местах, поэтому полей больше, чем кажется:

1. **карточка** в секции «Кейсы» на главной — обложка, 3 метрики, одна строка описания;
2. **страница разбора** отдельным адресом (в макете — `/work/<slug>`, окончательные адреса за вами) — крупная обложка, `Задача → Что сделал → Результат`, стек, ссылка;
3. **строка в журнале** (в макете — `/log`) — дата, тип-чип, заголовок, одна строка.

Всё это заполняется из одного файла. Ничего не дублируйте руками.

## 1. Поля одного кейса

Обязательные поля отмечены `*`. Все текстовые поля — **парой EN/RU**: английский язык на сайте
основной, русского перевода «потом» не бывает.

| Поле | Что это | Ограничения |
|---|---|---|
| `slug` * | Идентификатор в адресе `/work/<slug>` | латиница, цифры, дефисы; только строчные; не меняется после публикации |
| `order` * | Позиция в сетке кейсов | `01`–`06`, дальше по мере роста |
| `title` * | Название, как оно показывается (моно-шрифтом) | до 32 символов, иначе ломает карточку |
| `kind.en` / `kind.ru` * | Тип через `·`: `Website · Tilda migration` / `Сайт · Миграция с Tilda` | 2 слова + 2 слова |
| `category` * | Для фильтра над сеткой | `site`, `bot`, `ai`; можно два через пробел (`bot ai`) |
| `summary.en` / `summary.ru` * | Одна фраза в карточке: что это и главный факт | 150–210 знаков, ровно одно предложение |
| `metrics[3]` * | **Ровно три** чипа с метриками, каждый EN/RU | до 18 знаков каждый; цифра или короткий факт, без глаголов |
| `tech[]` * | Теги стека | 1–4 штуки, писать как в стеке сайта: `Python`, `aiogram 3`, `pytest`, `Docker`, `Nginx`, `HTML/CSS/JS`, `Claude CLI` |
| `link` * | Публичный адрес или `null` | `null` = карточка приглушается, курсор `not-allowed` |
| `linkNote.en/ru` | Обязательно, если `link: null` | например `Demo closed by the owner` / `Демо закрыто по решению владельца` |
| `repo` | Публичный репозиторий | сайт обещает «код можно прочитать до оплаты» — либо даём ссылку, либо убираем обещание для этого кейса |
| `accent` * | Цвет карточки (`--cc`) | один из: `#22D3EE`, `#A855F7`, `#FFB020`, `#4F46E5`, `#34D399`, `#94A3B8` (серый — только для закрытого) |
| `shotKind` * | Оформление слота обложки | `browser` (рамка браузера), `telegram` (окно чата), `closed` (ч/б + штриховка) |
| `body.task.en/ru` * | **Задача**: что было до вас, чем это мешало | 1 абзац, 2–4 предложения |
| `body.did.en/ru` * | **Что сделал**: решение и технические факты | 1 абзац, 2–4 предложения |
| `body.result.en/ru` * | **Результат**: чем всё кончилось, в цифрах | 1 абзац, 2–3 предложения |
| `screenshots[]` * | Список снимков, см. §3 | минимум 2 (`card` + `cover`), рекомендуется 4–5 |
| `date` * | Дата публикации кейса | `ДД.ММ.ГГГГ`; управляет порядком в `/log` («новое сверху») |
| `logLine.en/ru` * | Одна строка для ленты журнала | до 90 знаков, отличается от `summary` — короче и суше |
| `featured` | Особая карточка | `live` (яркая рамка + бейдж «Живое демо») или пусто |

Чего в кейсе быть **не должно**: отзывов клиента, если он их не давал в письменном виде;
цифр, которых вы не измеряли; названия клиента, если он не разрешил.

## 2. Файлы и папки

Движок ещё не выбран (см. «Открытые вопросы»), поэтому формат нарочно простой и переносимый:
один текстовый файл + папка картинок на кейс.

```
content/
  cases/
    01-th-neva-beauty/
      case.md              ← поля из §1 (front-matter) + три блока текста
      shots/
        card@2x.webp       1600×1000  — обложка карточки
        cover@2x.webp      1920×960   — обложка страницы разбора
        01-home.webp       1600×1000
        02-prices.webp     1600×1000
        03-tests.webp      1600×1000
    02-vn-neva-beauty/
      …
  log/
    notes/                 ← заметки (не кейсы), тот же принцип
    updates/               ← апдейты одной строкой
  prices.yml               ← единственный источник правды по ценам
```

Правила именования:

- Папка кейса = `<order>-<slug>`. Слаг совпадает с адресом `/work/<slug>`.
- Файлы снимков — строчные, латиницей, с номером и смыслом: `03-admin-panel.webp`, не `IMG_2841.png`.
- `@2x` в имени — мастер-файл двойной плотности; версию 1× генерирует сборка, руками не делаем.
- Никаких пробелов и кириллицы в именах файлов.
- Один кейс — одна папка. Не складывать снимки всех проектов в общую свалку.

## 3. Скриншоты

Все изображения лежат в репозитории и отдаются со своего домена: правило «ноль внешних запросов»
действует и на картинки. Каждому снимку нужен `alt` на двух языках.

| Роль | Файл | Размер мастера | Пропорция | Что должно быть в кадре |
|---|---|---|---|---|
| `card` * | `card@2x.webp` | **1600×1000** | 16:10 | Верх главной страницы или первый экран бота. Кадрируем верх — низ карточки всё равно закрыт вуалью. Читаемый заголовок, видно, что это законченный продукт |
| `cover` * | `cover@2x.webp` | **1920×960** | 2:1 | Тот же экран шире, для страницы разбора. Кадр «в полный рост», без обрезанных элементов по краям |
| `feature` | `0N-<что>.webp` | 1600×1000 | 16:10 | Главная идея проекта: экран с ценами, шаг квиза, клавиатура бота, лента канала |
| `proof` | `0N-<что>.webp` | 1600×1000 | 16:10 | **Доказательство**: отчёт Lighthouse с видимыми цифрами, зелёный вывод `pytest`, админка, лог дедупликации |
| `before` | `0N-before.webp` | 1600×1000 | 16:10 | Только для миграций: как было. Тот же участок страницы, что и в `after` |
| `og` | `og.webp` | 1200×630 | 1.91:1 | Для превью в мессенджерах: обложка + название проекта |

Технические требования:

- Снимать в тёмной теме сайта/приложения, если она есть, — обложка встаёт под вуаль цвета карточки.
- Ширина окна при съёмке: 1440px для десктопных экранов, 390px для мобильных (мобильный снимок
  ставим внутрь `feature`, не в `card`).
- Без курсора, без панелей закладок, без личных данных, без открытых вкладок с чужими сайтами.
- Персональные данные клиентов, телефоны, реальные заявки — замазать или заменить.
- Формат мастера — WebP качества ~82 или PNG, если много мелкого текста. Вес одного файла ≤ 400 КБ.
- У каждого снимка в разметке обязаны быть `width`, `height` и `loading="lazy"` (кроме `cover`
  на самой странице кейса) — иначе просядет Lighthouse.
- Скриншот закрытого проекта (`shotKind: closed`) всё равно нужен: он показывается в оттенках серого
  под диагональной штриховкой, поэтому мелкие детали в нём не читаются — берите общий вид.

## 6. Чек-лист: чем кейс убеждает покупателя

Кейс готов к публикации, когда в нём есть все пять пунктов:

1. **Конкретное число, а не прилагательное.** «25 страниц, 204 цены, 85 тестов» работает,
   «качественно и быстро» — нет. Три метрики в чипах — это не украшение, это главный аргумент.
2. **«Было → стало».** Одна пара цифр или пара скриншотов на один и тот же участок экрана.
   Без «было» результат нечем измерить: `−60% веса` убеждает только рядом с тем, от чего 60%.
3. **Проверяемая ссылка.** Живой сайт или бот, который открывается и работает прямо сейчас.
   Если ссылки нет (как у `th.neva.beauty`) — прямо сказать почему; закрытое демо с честной причиной
   выглядит лучше, чем битая ссылка.
4. **Понятно, какую проблему это решило.** Блок «Задача» пишется словами клиента и про его боль,
   а не про технологии. Технологии — в блоке «Что сделал».
5. **Доказательство на скриншоте.** Отчёт Lighthouse с видимым числом, зелёный прогон тестов,
   лог дедупликации. Одна такая картинка стоит абзаца обещаний.

И одно правило поверх всего: **лучше меньше кейсов, но с цифрами**, чем шесть красивых карточек,
за которыми нечего показать. Пустое поле лучше выдуманного.

## Открытые вопросы

- **CMS или плоские файлы.** Не решено. Формат выше нарочно движко-независимый: если появится CMS,
  поля переносятся один в один; если останутся файлы — работает как есть.
- **Публичные репозитории.** Сайт утверждает: «Каждый проект ниже — публичный репозиторий, код можно
  прочитать до оплаты», и в About указано «6 публичных репозиториев». Ссылок на конкретные репозитории
  ни в одном брифе нет — известен только аккаунт `https://github.com/jw-git-hub`. Пока владелец
  не даст шесть прямых ссылок, обещание не подкреплено: либо ссылки, либо смягчить формулировку.
- **Разрешения клиентов.** Можно ли называть салон, клинику и психолога и показывать их скриншоты —
  не подтверждено. По умолчанию считаем, что нельзя, и показываем проекты по доменам.
- **Даты.** В макете стоят даты 2026 года (например `15.03.2026` у первого кейса) — они макетные,
  поставлены для демонстрации ленты. Реальные даты публикаций даёт владелец. От даты зависит
  порядок в `/log` и строка «последняя запись N дней назад».
- **Заметки и апдейты.** Три заметки и три апдейта уже описаны в макете, но у них
  тоже нет реальных дат и нет самих текстов статей — есть только заголовки и по одной строке описания.
